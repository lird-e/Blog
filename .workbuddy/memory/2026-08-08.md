## 重大发现：Decap GitHub backend 认证方案从初始化起就无法工作
- 用户点 Login 后弹窗 `api.netlify.com/auth?provider=github&site_id=lird-e.github.io&scope=repo` 显示 Not Found
- 根因：**Decap 的 GitHub backend 不支持 PKCE 纯前端认证**（PKCE 是 gitlab/git-gateway 的特性）；config.yml 里的 `app_id` 对 github backend **完全无效**——GitHub backend 的 AuthenticationPage 写死 NetlifyAuthenticator（已读 decap-cms@3.15.1 源码证实），必须有 OAuth 服务器中间层
- Sveltia CMS 官方文档也证实：GitHub 的客户端 PKCE 是 Unimplemented（GitHub 官方 roadmap 未发布）
- 可行方案：A) 换 Sveltia CMS + PAT 登录（最快，零服务器）；B) Sveltia + Cloudflare Worker OAuth；C) 保留 Decap + 部署 OAuth 代理；D) 只用本地 serve.py 发文
