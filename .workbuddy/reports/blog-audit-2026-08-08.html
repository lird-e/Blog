🔴 高优先级 —— 现在就会出错或必然踩雷

以下问题一旦触发（或按现有说明操作）就会报错 / 404 / 数据损坏。

H1. Decap CMS 上传图片路径错误，插图的链接必 404
admin/config.yml : 18-19
站点部署在子路径 https://lird-e.github.io/Blog/，但 public_folder: "/assets/uploads" 是绝对路径。Decap 插入正文的图片地址会是 /assets/uploads/xxx.png，浏览器解析到域名根 lird-e.github.io/assets/... → 404。目前没传过图所以没暴露，一旦启用必坏。
修复：改为 public_folder: "/Blog/assets/uploads"，或改成相对路径 assets/uploads 并在正文用相对引用。
H2. 本地依赖说明缺 pyyaml，按提示装完必报 ModuleNotFoundError
publish.bat : 6-7 · build.py : 9（import yaml）
publish.bat 只提示安装 markdown pygments，但 build.py / serve.py 都 import yaml。按提示操作后本地构建直接报 No module named 'yaml'。CI 的 deploy.yml 装了 pyyaml 所以线上没事，本地必踩。另外当前机器还没有 .venv，publish.bat 现在根本跑不起来。
修复：publish.bat 提示补上 pyyaml（或新建 requirements.txt 统一管理）；本机先执行 python -m venv .venv 并安装 markdown / pygments / pyyaml。
H3. serve.py 表单双重 URL 解码，正文会被二次解码损坏
serve.py : 149-150
parse_qs() 已自动解码，代码又对取值 unquote() 一次。正文里字面出现的 %xx（如 URL 编码链接 %E4%B8%AD、%20）会被再次解码。已实测：提交 http://a.com/%E4%B8%AD，落盘后变成 http://a.com/中，原文被改写。
修复：去掉多余的 unquote，只保留 parse_qs 的结果。
H4. 文章排序按文件名而非日期，新文章可能排到最旧
build.py : 152 · serve.py : 157-163 · admin/config.yml : 26
build.py 用 sorted(glob("*.md"), reverse=True) 按文件名排序，但日期存在 frontmatter 里。serve.py 发布的新文件是 slug.md（无日期前缀、字母开头），reverse 排序时字母开头的排不过数字开头的旧文件 2026-02-02-writing.md，新文章会被排到列表后面。三处（本地表单 / Decap / 生成器）的文件命名规则互不统一。
修复：排序改为按 frontmatter 的 date 字段；文件名统一为 YYYY-MM-DD-slug.md 约定。

🟠 中优先级 —— 体验、安全与一致性

不立即出错，但会影响 SEO、安全、观感或维护。

M1. slug 由标题生成，同标题文章互相覆盖
build.py : 62-64, 161
Hello World 与 hello world、以及任何"同名不同日期"的文章会生成同一个 slug，输出 HTML 互相覆盖，只剩最后一篇。
修复：slug 加上日期前缀（如 2026-08-08-标题），与文件名约定对齐。
M2. 中文标题生成中文 URL，链接不稳定
build.py : 62-64（slugify 保留中文）
现有文章 URL 是 /posts/用-60-行-python-写一个静态博客生成器.html：浏览器里全是 % 编码、SEO 不友好，且标题一改 URL 就变，旧链接全部失效。
修复：URL 建议用英文/拼音 slug（frontmatter 加 slug 字段优先），中文仅保留在页面标题里。
M3. 文章页标题/日期未转义（首页有转义，文章页漏了）
build.py : 202-206（title/date 直接替换进模板）· 239（tag 页 <title> 未转义）
首页卡片用了 escape()，但文章页 <h1>{{title}}</h1> 和 time 直接插入原始值。标题含 < / & 会破坏页面结构，含脚本片段可注入 HTML。
修复：文章页与标签页标题统一走 escape()。
M4. 本地后台无认证 + 绑定 0.0.0.0
serve.py : 181
监听所有网卡，且 /admin 的 POST 无任何鉴权，局域网内任何人都能往你的博客发文章；SimpleHTTPRequestHandler 默认支持目录遍历。个人本机工具可接受，但别在公司网络跑。
修复：默认绑 127.0.0.1，或加一个简单访问口令。
M5. 深色模式下代码高亮失效、代码块突兀
assets/style.css : 75-76 · build.py : 282（只生成一份亮色 pygments 样式）
[data-theme="dark"] .codehilite *{color:inherit !important} 把所有语法 token 颜色覆盖成单一色（高亮等于没高亮），代码块还被强制成浅色背景，与深色主题脱节。
修复：深色主题改用 style="github-dark" 的 pygments 样式，去掉 !important 覆盖。
M6. 两套发文后台并存，行为不一致易困惑
serve.py（本地自定义表单）/ admin/（云端 Decap CMS）
本地打开 /admin 看到的是 serve.py 自建表单（保存到本地并 build）；线上 /admin 是 Decap CMS（直接提交 GitHub）。两者功能、流程完全不同，文档里只写了"Decap CMS 已集成"，容易误以为是一个东西。
修复：页面或 README 里明确标注"本地表单仅本机可用，线上请用 Decap CMS"，或统一成一套。
