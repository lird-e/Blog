> 远程访问路由器及其下设备的多种方案：KVM、端口转发/DMZ、GoodCloud 云平台、Tailscale 虚拟组网。适用于远程运维与异地访问。

## 一、方案概览

| 方案 | 机制 | 适用场景 |
|------|------|---------|
| KVM | 硬件级带外管理（视频/键鼠/虚拟媒体） | 远程操作无头设备、服务器 |
| 端口转发 / DMZ | 公网/上级网段 NAT 穿透到内网设备 | 固定端口服务对外发布 |
| GoodCloud | 厂商云平台中转，设备绑定后远程 GUI/SSH | 多设备集中云管理 |
| Tailscale | 基于 WireGuard 的虚拟组网 | 异地像内网一样访问 |

## 二、远程 KVM

### 访问方式

| 方式 | 要点 |
|------|------|
| 域名访问 | 浏览器输入 `glkvm.cn` |
| IP 访问 | 路由器管理页查 KVM IP，输入 IP + 密码；**需同一局域网** |
| Cloud Service | 绑定设备后，glkvm 网页/客户端平台远程访问 |
| GLKVM App | 手机 App 登录账号访问 |
| Tailscale/ZeroTier/NetBird | 电脑装 Tailscale，GLKVM 平台「应用中心」绑定后访问 |

### Console 实用功能

- **OCR**：直接读取图片中的文字
- **剪贴板**：中转功能，节约重复输入
- **快捷键**：远程操作中使用常用快捷键

### 虚拟媒体（Virtual Media）

1. 拖拽/点击/网址上传文件到虚拟媒体
2. 将虚拟媒体**挂载到被控端**（相当于虚拟 U 盘/光驱）
3. 停止共享即弹出

### Fingerbot 手指机器人

- 通信：KVM 通过 **USB 蓝牙接收器**与手指机器人通信
- 控制参数：按压时长（Time）、按压强度（Strength）
- 兼容性：**仅兼容 GL.iNet KVM**

### ATX 板

- Interface 4：连接机箱前面板控制线；Interface 5：连接主板 F_PANEL；**两者可互换**
- 安装注意：核对接口极性（不同机箱有差异）；9 针排线只用于其中一个接口，另一个用机箱自带排线
- **无法控制开关机排障**：① 直接按机箱电源键排除硬件故障 ② 翻转 POWER SW 接头极性 ③ 检查 F_PANEL 接线、丝印朝外 ④ 升级 KVM 固件

## 三、端口转发与 DMZ

### 端口转发 vs 开端口

| 功能 | 机制 | 作用对象 |
|------|------|---------|
| 端口转发 | 外网访问 WAN IP:端口 → NAT 转发到内网设备对应端口 | 内网设备（NAS、服务器、摄像头） |
| 开端口 | 防火墙放行某端口入站数据包 | 路由器本机（远程管理） |

### 远程访问的前提

- 同网段可达 + 端口放行
- **非公网 IP 限制**：WAN IP 为私网地址（如 10.x）时，跨网段无法访问，需 VPN / 虚拟局域网
- 开管理端口有被爆破入侵的风险

### DMZ vs 端口转发

| 维度 | DMZ | 端口转发 |
|------|-----|---------|
| 暴露范围 | 内网设备**所有端口**对外映射，绕过防火墙 | 仅放行单个/一段业务端口 |
| 安全性 | 攻击面大、风险极高 | 按需开放、防护边界清晰 |
| 适用 | 多端口业务、临时全网连通调试（不建议长期启用） | 固定端口服务长期发布 |

> 优先级最高的规则生效：DMZ 优先级高于端口转发时，访问 WAN IP 直接跳转 DMZ 主机。

## 四、GoodCloud 云平台

### 设备管理

- **Band Devices**：已绑定设备列表（Name、Status、Model、Version、MAC、IP、Compile Time）
- **Shared Devices**：已分享设备
- 设备详情页 Internet 设置：Protocol（DHCP/PPPoE/Static）、TTL、IPv6 TTL、MTU（以太网 1500 / PPPoE 1492）、VLAN ID（光纤入户按运营商指定填写，DHCP 内网留空）
- 设备详情页 WiFi 设置：TX Power、SSID、Security、Password、Visibility、Mode、Bandwidth、Channel 等

### 远程 GUI / SSH

- 设备详情页可直接远程访问管理页（GUI）和后台（SSH）
- **选项置灰**：路由器端未开启远程功能，到路由器 GoodCloud 模块打开

### 设备分享

- **Individuals**：分享给个人账号/邮箱（协同管理）
- **GL.iNet Technical Support**：分享给技术支持（故障报修）
- 参数：Recipient、Notes、Auto Expire Sharing（到期自动回收远程权限）

### ORG 权限（升级后）

新增/增强：Groups（分组管理）、Settings Templates（模板批量部署）、Administration（组织部门/成员/通知策略）、API Integrations（API 密钥）；Devices 范围扩大至整个组织。

**批量模板注意**：同组设备型号、固件须一致，否则批量应用会失败或不生效。

## 五、Tailscale 虚拟组网

### 基本概念

- 基于 WireGuard 的虚拟组网，把分散设备组成虚拟局域网
- 每台设备有 **Virtual IP**（Tailscale console 的 ADDRESS）
- 组网内的设备即使不在同一物理局域网，也能像内网一样互通

### 两个关键开关

| 开关 | 作用 |
|------|------|
| Allow Remote Access LAN | 同 Tailscale 网络设备可通过**局域网 IP** 访问该路由器下所有内网设备（需在 console 编辑路由设置） |
| Allow Remote Access WAN | 可通过该路由器访问它 **WAN 口上游**网段的设备 |

### 验证流程

1. 电脑装 Tailscale，与路由器绑定同一网络，确保 Connected（为模拟异地，电脑不连该路由器，可连手机热点）
2. 找到路由器 Virtual IP
3. 验证：ping Virtual IP → 浏览器访问 → SSH 访问，均可通
4. 开启 Allow Remote Access LAN，到 console 编辑路由设置
5. 验证通过 LAN IP 访问：ping / 浏览器 / SSH 全通

### 排障

- Virtual IP 通但 LAN IP 不通 → 未开启 Allow Remote Access LAN 或 console 路由未配置
- 设备不在 Connected → 检查账号绑定与设备登录
- 两台路由器 LAN IP 相同 → 先改为不同网段
